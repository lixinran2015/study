# 第 4 章：综合实战 — 记账小应用

经过前面三章的学习，你已经掌握了 Prompt 的基本写法、Vue 3 的数据绑定、以及 HTML 文件的调试方法。这一章，我们要把这些知识串起来，做一个**完整的功能性小应用**。

---

## 学习目标

- 学会把一个大需求拆成多个小任务，逐个完成。
- 学会在 Claude Code 的辅助下，从零开始搭建一个 Vue 3 单页应用。
- 学会用 `computed` 做自动统计，用 `localStorage` 做数据持久化。
- 学会在代码能跑之后，进一步审校和优化。

---

## 项目效果预览

最终你会得到一个单文件 HTML 网页：

- **顶部**有三个白色统计卡片，分别显示总收入（绿色）、总支出（红色）和结余（黑色）。
- **中部**有一个表单，可以选择收入/支出、分类、金额、备注和日期，点击按钮后记录会添加到列表中。
- **底部**是收支明细列表，按日期倒序排列，收入显示 `+100.00`，支出显示 `-50.00`，每条记录都可以删除。
- 所有数据都会**自动保存到浏览器本地**，刷新页面后记录不会丢失。

💡 **小提示：** 本章示例使用了浏览器的 `localStorage` 功能。由于 Safari 在本地文件（`file://`）模式下会禁用 `localStorage`，**建议你用 Chrome 或 Edge 浏览器打开 HTML 文件**，以确保数据能正常保存。如果确实需要在 Safari 中查看，代码也已经做了兼容处理，不会出现页面空白，只是刷新后数据会清空。

## 分步实现路径

大项目不要一次性扔给 AI 做，拆成一步一步来，出错也更容易定位。

### Step 1: 搭建页面骨架

先让 Claude 帮你把静态页面搭出来，不用着急加功能。

**Prompt 示例：**

> 请帮我写一个单文件 HTML 网页，使用 Vue 3 CDN。先只做记账应用的静态页面：顶部放三个统计卡片（总收入、总支出、结余），中间是一个表单（类型、分类、金额、备注、日期、添加按钮），下面是一个空白列表区域。样式简洁美观。

---

### Step 2: 添加数据绑定

页面有了之后，下一步让表单和列表“动起来”。

**Prompt 示例：**

> 请帮我在这个记账应用里加上数据绑定功能：点击"添加记录"按钮后，表单里的数据会显示到下方的列表中。列表按日期倒序排列。

---

### Step 3: 加入分类和收支类型

收入和支出的分类通常是不一样的，而且颜色也要区分。

**Prompt 示例：**

> 请帮我完善记账应用：收入类型显示绿色正数（+100），支出类型显示红色负数（-50）。分类根据收支类型动态变化：收入时可选"工资、其他"，支出时可选"餐饮、交通、娱乐、购物、其他"。

---

### Step 4: 实现统计区域

顶部的三个数字不能写死，要根据列表内容自动计算。

**Prompt 示例：**

> 请帮我在记账应用顶部加上自动统计：总收入、总支出、结余会根据列表中的记录实时计算。

---

### Step 5: 添加删除功能和数据持久化

最后补上删除和本地存储，应用就完整了。

**Prompt 示例：**

> 请帮我在每条记录右侧加一个删除按钮，点击确认后删除。同时用 localStorage 保存数据，刷新页面后记录不会丢失。

---

## 用 Claude Code 审校代码

代码能跑不代表代码质量好。写完之后，可以让 Claude 帮你做一次 review。

**Prompt 示例：**

> 这段代码已经能跑了，请帮我检查一下结构和逻辑，给我优化建议。

常见的优化点包括：

- 用 `computed` 代替在 `methods` 里手动计算统计值
- 用 `watch` 监听类型切换，自动清空不合适的分类
- 给列表项加上唯一的 `:key`，提升渲染性能
- 把验证逻辑抽成独立的方法，代码更清晰

## Bug 定位教学

**场景：** 有同学说："我加了删除功能之后，统计数字没有更新。"

**排查思路：**

如果你是用 `computed` 属性（比如 `totalIncome`、`totalExpense`、`balance`）来计算的，那删除记录后数字**应该会自动更新**。如果数字没变，先检查：

1. 你是不是把统计写成了 `data` 里的普通变量，而不是 `computed`？
2. 你是不是在删除记录时，直接修改了数组的某个元素，但没有触发 Vue 的响应式更新？（Vue 3 中要用 `splice` 或重新赋值数组）
3. 你是不是在 `removeRecord` 里删错了索引？（注意列表是倒序的，`sortedRecords` 的索引和原始 `records` 的索引不一定相同）

**关键经验：** 描述 bug 时，要讲清楚**预期结果**和**实际结果**。比如：

> "我点击删除后，预期顶部的总支出应该减少 50 元，但实际上数字没有变化。"

这样别人（或 Claude）才能更快定位问题。

---

## 教学重点小结

1. **大项目要拆成小任务**：先做骨架，再绑数据，再加样式，最后补功能。
2. **用 Claude Code 做代码审校**：能跑只是第一步，review 之后代码会更健壮。
3. **描述 bug 时要讲清楚预期和实际**：这是程序员最重要的沟通技巧之一。

## 本章挑战

在基础版本之上，尝试添加一个**按月筛选**功能：

- 在统计卡片下方加一个下拉选择框，选项包括"全部"和所有记录中出现过的年月（如 `2025-03`、`2025-04`）。
- 选择某个月后，列表只显示该月的记录，顶部的统计数字也同步更新。
- 默认显示"全部"。

**提示：**

- 可以用 `slice(0, 7)` 从日期字符串中提取 `yyyy-MM`。
- 用 `Set` 去重，得到所有唯一的月份。
- 用 `computed` 属性 `filteredRecords` 来统一处理筛选逻辑，统计和列表都基于它计算。

**参考 Prompt：**

> 请帮我在记账应用里加一个按月筛选的功能，在顶部加一个下拉框，选择月份后只显示该月的记录，统计数字也同步更新。

挑战版的参考代码已放在 `examples/04-accounting-app-challenge.html`。
